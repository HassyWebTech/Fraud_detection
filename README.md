# Behavioral Account Takeover Detection

ICSC 2026 Universities Hackathon — Track A (Financial Services & Digital Payments)

Detects account takeover in real time using behavioral signals (typing rhythm,
device recognition, transaction habits) rather than relying solely on
PIN/OTP correctness — because a stolen credential still passes a
correctness check, but rarely matches the real owner's behavior.

## Quickstart

```bash
# 1. Create and activate a virtual environment (keeps this project's
#    dependencies isolated from your system Python)
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt
# for running tests too:
pip install -r requirements-dev.txt

# 3. Initialize the database
cd src
python db.py

# 4. Generate synthetic data (already included in data/, but reproducible)
python generate_data.py --n_users 2000 --n_sessions 50000 --seed 42

# 5. Build behavioral features
python features.py

# 6. Train the model
python train.py

# 7. See explainability output in the terminal
python explain.py

# 8. Try the offline/degraded-mode fallback
python fallback_rules.py

# 9. Check real scoring latency (milliseconds)
python benchmark_latency.py

# 10. Run tests
python -m pytest ../tests/ -v

# 11. Run the interactive demo
cd ..
streamlit run demo/app.py
```

When you're done working, run `deactivate` to leave the virtual environment.

## Key results (test set, time-based holdout)

- **Combined recall (block + monitor tiers): 100%** — zero attacks went completely untracked
- Hard-block false positive rate: 0.98% of genuine sessions actually stopped
- 3.5% of all sessions routed to analyst monitoring queue (flagged, not blocked)
- Latency: p99 of 1.86ms (ML model), sub-millisecond (offline fallback) — both ~500x under the sub-second requirement
- Known weak spot: "patient/low-and-slow" attack pattern has the lowest single-threshold recall (79%) of the four attack types — see write-up for full honesty on limitations.

## Data

All data is synthetic, generated by `generate_data.py` with a fixed seed
for reproducibility. No real customer data was used at any point. See
the technical write-up for full data generation methodology.
